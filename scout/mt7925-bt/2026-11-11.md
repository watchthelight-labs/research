# mt7925-bt: 2026-10-31 to 2026-11-11

Read from GitHub only. Nothing below is reproduced on our machine.

- Warm restart. [thanhnndev/mt7925-macos](https://github.com/thanhnndev/mt7925-macos/blob/main/docs/BLUETOOTH.md) sees `wmt op 1 flag 0: no event` when the firmware is still running after a warm reboot, and skips the first two firmware sections then. [qqwqtzd/mt7927-hackintosh](https://github.com/qqwqtzd/mt7927-hackintosh) carries a pre-reset for our loader, checked across macOS, Windows and macOS again. Both bear on [WTLWireless #11](https://github.com/watchthelight-labs/WTLWireless/issues/11). Medium for Bluetooth, Low for the USB enumeration part.
- Bluetooth turning off after seconds. Three repositories name two NVRAM keys as the cause when they are missing: `bluetoothExternalDongleFailed` = 00 and `bluetoothInternalControllerInfo` = 14 zero bytes ([LOQ 15IAX9](https://github.com/NumanLUAU/LOQ-15IAX9-Hackintosh), [OMEN 8f06](https://github.com/xiaoyizpast/Hackintosh-OMEN-8f06/blob/main/README.md)). Our README already lists both. None of the three shows a log of an MT7925 that dies after seconds, so for [WTLWireless #9](https://github.com/watchthelight-labs/WTLWireless/issues/9) this is a thing to rule out, not a cause. Medium.
- BLE devices that hang. thanhnndev's `BtLeDlFix` patches bluetoothd so LE devices leave `LE_READY_WAIT_FOR_LENGTH` on this controller. Found on Sequoia, untested on Tahoe.
- AirPods that pause. [SimpleMtkBtFw](https://github.com/flxxxxddd/SimpleMtkBtFw) (GPL-3.0): HCI_Read_Clock returned handle 0; `Which_Clock=1` fixed it there. It also warns that renaming the USB product string makes bluetoothd abort.
