# MediaTek MT7925 Wi-Fi: what moved, 2026-10-15 to 2026-10-22

Target: [WTLMtkWireless](https://github.com/watchthelight-labs/WTLMtkWireless) (MtkWlan). Open issues: [#1](https://github.com/watchthelight-labs/WTLMtkWireless/issues/1) Wi-Fi gone after a restart, [#2](https://github.com/watchthelight-labs/WTLMtkWireless/issues/2) other MediaTek cards, [#3](https://github.com/watchthelight-labs/WTLMtkWireless/issues/3) use during install. Confidence uses High / Medium / Low / Unverified.

## Actionable

**A recovery path for a card left wedged by a warm restart** (High, code read). [SimpleMtkWlan PR #7](https://github.com/laobamac/SimpleMtkWlan/pull/7) by flxxxxddd brings MT7921/RZ608 up end to end on macOS 15.8.1:
- chunk size for the firmware load and MSI
- a TX DMA stall on frames split over several mbufs
- group-key receive through a software CCMP fallback
- stale STA records when switching networks
- HT20 with A-MPDU and receive Block Ack

One commit, "Recover a wedged chip at attach: WFSYS reset, then PCIe FLR", matches our [#1](https://github.com/watchthelight-labs/WTLMtkWireless/issues/1): a warm reboot leaves the card powered and "driver own" fails. It tries a WFSYS reset first and then a PCIe function level reset. It's GPL-2.0, so idea only. It can't help the part of #1 where the card is gone in Windows too until a cold power-off.

**A working MT7922 port to point testers at** (High). [hbyonly1/itlmt7922-wifi](https://github.com/hbyonly1/itlmt7922-wifi) (Clear BSD, v0.2.2, created 2026-10-17) ports itlmt7925 to the older Connac2 firmware family for MT7922/RZ616 (14c3:0616). It's tested on real hardware on macOS 15.8.1, with WPA2/CCMP and HT/VHT working, through an Ethernet back end and a menu app. Its `docs/PORTING.md` lists the register, TXWI/RXD and key-table differences that [#2](https://github.com/watchthelight-labs/WTLMtkWireless/issues/2) asks about. Credited in our README.

## Notable

- **Two more machines run our kexts** (High). [BelikPePe-UA/legion5-15irx10-hackintosh](https://github.com/BelikPePe-UA/legion5-15irx10-hackintosh) runs a Legion 5 15IRX10 on Sequoia 15.8.1. It uses MtkWlan 0.11.0 with MtkWlanNative 0.4.10 and reports the native Wi-Fi menu, WPA2/WPA3 and 93/93 Mb/s. [Game-5040/hackintosh-hp-8f06-macos26](https://github.com/Game-5040/hackintosh-hp-8f06-macos26) runs an HP OMEN 16 on Tahoe 26.7.1 with MtkWlan 0.11.3 and MtkWlanNative 0.4.11. Both credit us.
- **The 15IRX10 guide's first boot panicked** with `thread_call group 'high' reached max thread cap` (Low on the cause). That panic is fixed in NullMoth 2.4.3, which the guide runs, so it's probably not ours. We don't know which change made their setup stable.
- **AirportMtkWlan stays Sequoia only** (High). [mnnobre/AirportMtkWlan#2](https://github.com/mnnobre/AirportMtkWlan/issues/2): the kext doesn't load on 26.7.1 (MaxKernel 24.99.99). This is what our #2 already says.
- **A claimed native MediaTek stack on Tahoe** (Unverified). [GeekAudio/mediatek-sunrise-hackintosh](https://github.com/GeekAudio/mediatek-sunrise-hackintosh) says 26.7.1's KDK has an "AppleSunrise" driver usable with a device-id spoof. The repo was all committed in one day by an AI agent and ships kext binaries we can't verify, and by its own account Apple ships Wi-Fi firmware only for MT7932, not for MT7922 or MT7925. Don't use those binaries. The only way to check is to look for the driver in our own 25G241 KDK.

## Third run (afternoon): two fixes ported

- **Scan cache** ([thanhnndev 4257353](https://github.com/thanhnndev/ga403wm-hackintosh/commit/4257353065b34181b42993c946fb0956c47c6e32), Clear BSD): a 48-slot BSS table loses the 2.4 GHz networks in a crowded place, because 5 GHz is scanned last and eviction takes the oldest entry. We had the same design. Ported as a 128-entry cache that evicts what the running scan has not heard ([MtkWlan branch scan-cache-roc](https://github.com/watchthelight-labs/WTLMtkWireless/tree/scan-cache-roc)). High that the bug exists here; the fix is built, not yet tested.
- **Join ROC** ([mt76 fddc43d](https://github.com/openwrt/mt76/commit/fddc43d51481ca8c0e2d16a88caaca528791f359)): releasing the join ROC right after association made the chip miss message 3 of the WPA2 handshake (reason 15). We released it at the same point; the branch now keeps it until the keys are installed. We never saw the failure ourselves. Medium.
- Ideas for I-081 and I-096, not ported: [mt76 7adc7a8](https://github.com/openwrt/mt76/commit/7adc7a8e83980ede034382c3c5062232ce1e4b53) (MCU events dropped when "removed" is set too early), thanhnndev's link-loss recovery [5f00557](https://github.com/thanhnndev/ga403wm-hackintosh/commit/5f00557b5ed4377b6cb0f45a4e1c9cab5503163f).
