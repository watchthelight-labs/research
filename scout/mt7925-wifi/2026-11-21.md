# mt7925-wifi and the native front end: 2026-11-13 to 2026-11-21

Read from GitHub only. Nothing below is reproduced on our machine.

- **Linux mt76 already has the channel-switch path we are missing.** Our link drops when the access point changes channel (I-139). In mt76's mt7925 station code the driver arms a timer for the beacon interval times the announced count, and when it fires it joins the new channel with a remain-on-channel request, updates the BSS info with the new channel definition, ends the request and reports the switch done ([main.c](https://github.com/openwrt/mt76/blob/master/mt7925/main.c), `mt7925_csa_work`). The commits of 18 to 20 November only harden locking around it. mt76 is ISC, and we port from it already. Confidence: High for the recipe, Medium that it fixes our drop until it runs on hardware.
- **mt76 has no firmware roaming either.** It only reports beacon loss and leaves roaming to the host. So for I-140 the work is on the macOS side: fast scans and a join that honours the BSSID the system picks. Confidence: High, read from source.
- **The MT7927 repo built on our kexts says it added RSSI roaming and an MT7927 path.** [qqwqtzd/mt7927-hackintosh](https://github.com/qqwqtzd/mt7927-hackintosh) (AMD RZ717) reports HE 160 MHz, WPA2 and sleep and wake on its own machine, and roaming that is a one to three second drop and rejoin. We asked for those patches as pull requests on 12 November, no answer yet. Their claims, not measured by us. Confidence: Medium.
- **AirportMtkWlan 2.1.6 to 2.2.2** (MT7921 and MT7922 only, GPL-3.0, no code of ours in it) fixed a warm-reboot failure by testing the firmware-ready bits exactly instead of "not zero", so a half-loaded chip gets its firmware again, and by waiting 500 ms for driver ownership instead of 50 ms ([v2.2.2](https://github.com/Arxusion/AirportMtkWlan/releases/tag/v2.2.2)). Both are worth checking in our load path. Its Skywalk commit only adds capability getters and puts AWDL behind a boot argument. Ideas only. Confidence: High for what the diffs do.
- **ForbiddenItlwm fixed two things that can hide in any net80211-style stack.** The SHA-256 key derivation used a 23-byte label and 64 bytes of output where the standard says 22 and 48, which breaks WPA2-SHA256 and SAE keys, and leaving a network sent no deauth so the access point refused the next join ([PTK commit](https://github.com/retropineaple/ForbiddenItlwm/commit/ba7b0b3d07), [rejoin commit](https://github.com/retropineaple/ForbiddenItlwm/commit/9645b5ed06)). GPL-2.0, ideas only. We should check our leave path and our key derivation for the same two mistakes. Confidence: High that the bugs are real there, Unverified for our code.
- **RTL8814Native fixed auto-join when the adapter shows up late at boot** and tuned its AWDL channel hopping ([release](https://github.com/DrogaBox/RTL8814Native/releases/tag/awdl-preview-20261117)). AWDL is still absent from WTLWireless, so this stays reference material.
- **Three more machines run our kexts and say so.** A Legion Y7000P IRX10 EFI ships MtkBt, LegionBtFix and the Wi-Fi kexts on 26.7.2 ([repo](https://github.com/Cube-geometric/Hackintosh-Legion-Y7000P-IRX10-EFI-with-MT7925-and-Trackpad)). An AMD ThinkBook 16p G6 ADR lists WTLWireless 0.15.0 with the native menu on 26.7.1 to 26.7.3 and notes there is no wake handling ([repo](https://github.com/Yangcheng811/ThinkBook-16p-2025-G6-ADR-Hackintosh)). A third Y7000P owner swapped the card for a Qualcomm one and links our driver as untested ([repo](https://github.com/xavierbe278/legion-y7000p-irx10-83nn-hackintosh)). README claims, no logs from them yet.

Skipped: Intel and Realtek AirDrop forks, an MT7902 repo with no content, and EFI folders for other cards.
