# mt7925-wifi: 2026-11-10 (quick run, window 2026-10-31 to 2026-11-10)

## Actionable

**[qqwqtzd/mt7927-hackintosh](https://github.com/qqwqtzd/mt7927-hackintosh): our three MediaTek kexts ported to the
MT7927 (MT6639).** The README (Chinese, status dated 2026-11-08) describes a working daily driver on Tahoe 26.x:
2.4 and 5 GHz, HE at 160 MHz with a negotiated 2064 Mb/s, WPA2, Bluetooth A2DP and LE, sleep and wake, and a roaming
policy that picks the stronger access point by RSSI. The repo carries copies of WTLMtkWireless, WTLWifiMenu and
WTLMtkBluetooth and a folder [UPSTREAM](https://github.com/qqwqtzd/mt7927-hackintosh/tree/main/UPSTREAM) with six
patches meant to be sent back: `roam-0001` to `roam-0004` for the core, and `cmd-0001` and `cmd-0002` for the menu
kext (16 more apple80211 requests let through, plus getNSS, CHANNELS_INFO, setPM_MODE and setROAM_PROFILE). The
patches are marked ISC, the same licence as ours.

Why it matters: we have no MT7927 here, and the plan for one driver across the MT792x family lists that chip as
"matched but opt-in, no hardware". This is hardware and a working port. They also report that 160 MHz showed up as
20 MHz in the channel display because the width code 3 fell into the default branch. Our menu kext has the same gap
(`MtkWlanNativeReq.cpp` only sets the 80 MHz flag); it is latent for us because the core stops at 80 MHz.

What we have read: the README and the UPSTREAM notes. We have not read the patch bodies or built anything.
Confidence: Medium for "it runs on their machine", Unverified for the rates. Next: read the six patches, and ask the
author whether they would send them as pull requests.

## Notable

- **[cao5555/mt7925-awdl](https://github.com/cao5555/mt7925-awdl)** (BSD-3-Clause-Clear, created 2026-11-10): AirDrop
  receive on an MT7925 on 25G332, built on thanhnndev's driver and a Python receiver. The README gives an ack rate of
  about 7 %, so large transfers stall. Its useful find is on the Bluetooth side: macOS never starts LE advertising on
  this controller, so the patch programs LE extended advertising from a kext. That bears on our Bluetooth loader as
  much as on Wi-Fi. README only. Confidence: Medium.
- **[yusufcanyavic/YYavicWiFi v0.8.0](https://github.com/yusufcanyavic/YYavicWiFi/releases/tag/v0.8.0)** (MT7922,
  GPL-3.0, ideas only): posts a link-quality update every 4 s because macOS drops a network after 60 s without one.
  We found the same rule and already post it, so this is an independent confirmation. Confidence: High that both
  drivers do it, Medium on the 60 s figure.
- **[Arxusion/AirportMtkWlan v2.0.0](https://github.com/Arxusion/AirportMtkWlan/releases/tag/v2.0.0)** (MT7921 and
  MT7922, GPL-2.0, ideas only): commit
  [06eeeffb](https://github.com/Arxusion/AirportMtkWlan/commit/06eeeffb) clears two card capability bits
  (concurrency, AWDL data info) to fix "on in Control Center, off in System Settings". We set neither bit, so
  nothing to do. The release also lists WPA3-SAE, FT and HE160; those we judged from titles only.
- **[laobamac/SimpleMtkWlan#9](https://github.com/laobamac/SimpleMtkWlan/issues/9)**: in a thread about an MT7921
  whose data RX ring stays empty on 26.7.2, a commenter documents the 0xc9 scan-result request and its flags and
  traces their own failure to OCLP root patches. We answer 0xc9 already. Read through a summary, not line by line.
- **[qiqco/MT7922-macOS-Driver](https://github.com/qiqco/MT7922-macOS-Driver)**: still binaries only. The README
  keeps the warm-restart panic (1 in 5 to 20, cured by a cold power-off), the pattern of
  [WTLMtkWireless#1](https://github.com/watchthelight-labs/WTLMtkWireless/issues/1).
- **[xiaoyizpast/Hackintosh-OMEN-8f06](https://github.com/xiaoyizpast/Hackintosh-OMEN-8f06)**: an HP OMEN EFI that
  uses both of our Wi-Fi kexts, and a small menu bar app over `mtkwifi` for macOS 26.0. Linked from our README
  ([#7](https://github.com/watchthelight-labs/WTLMtkWireless/issues/7)); we have not reviewed the app.
