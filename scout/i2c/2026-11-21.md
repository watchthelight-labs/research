# i2c: 2026-11-13 to 2026-11-21

Read from GitHub only. Nothing below is reproduced on our machine.

- **VoodooI2C reports a level-triggered GPIO pin as edge-triggered, and interrupts stall.** In [#591](https://github.com/VoodooI2C/VoodooI2C/issues/591) the reporter traced it on a Tiger Lake machine (macOS 26.7.2): the interrupt event source asks the device nub for the interrupt type before the pin's type has been set on the GPIO controller, gets "edge", does not mask the line, and delivery stops after about 0.3 seconds. Forcing "level" gave a 15 hour run with touchpad and touchscreen on interrupts. Our Arrow Lake touchpad uses a GPIO interrupt too, and our drafted VoodooGPIO change is about that interrupt. We checked our DSDT the same day: the touchpad's pin is declared `GpioInt (Level, ActiveLow)`, so this ordering bug applies to our case and has to be ruled out. A fix in the nub would not depend on the GPIO driver. One machine, no maintainer answer yet. GPL-3.0, ideas only. Confidence: Medium.
- **VoodooI2C now looks up the GPIO controller by class name.** Commit [927797d](https://github.com/VoodooI2C/VoodooI2C/commit/927797d4fcf5aaf2f4ccddd3daafd93f53d3adbf) replaces a cross-kext `OSDynamicCast` with `metaCast("VoodooGPIO")`, because the class symbol could resolve to a bad address when OpenCore injects the kexts, which page-faulted in `getGPIOController`. Unrelated to the interrupt type. We should check our kext for the same pattern. Confidence: High that the change is as described.
- **A ROG Strix SCAR 18 on the macOS 27.2 beta uses LegionI2CArrowLake and reports trouble.** With the touchpad attached the system freezes hard, and boot waits four to five minutes in `IOKitWaitQuiet` ([repo](https://github.com/saeckl/ROG-Strix-SCAR18-G835LXG-macOS27)). Their report on one laptop, on a beta we have not run. It goes on our list for macOS 27. Confidence: Medium.

Skipped: a touchscreen tracking-ID bug and a Synaptics descriptor override, neither on our hardware.
