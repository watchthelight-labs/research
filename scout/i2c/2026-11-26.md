# i2c: 2026-11-21 to 2026-11-26

Read from GitHub and one kernel database. Nothing below is reproduced on our machine.

- **A third-party Arrow Lake-H laptop polls a Goodix pad and needs a glitch guard.** The moto book 60 pro (Core Ultra 5 225H) has a Goodix GXTP5100 on I2C0. Its controller `8086:7778/7779` is not in VoodooI2C and its GPIO `INTC105E` has no VoodooGPIO table, so it runs `-vi2c-force-polling` ([README](https://github.com/sortedcord/MotoBook60Pro-Hackintosh-EFI/blob/main/README.md)). Under polling the cursor jumped, so the owner built VoodooI2CHID with samwu07's glitch-guard patch. It re-reads frames with an impossible finger jump and votes on touched frames. A second patch reads the slot size from the frame length (5 bytes and 32-byte frames here, 7 and 42 on the ThinkBook) ([patch](https://github.com/sortedcord/MotoBook60Pro-Hackintosh-EFI/blob/main/accel/candidates/voodooi2chid-glitch-guard/glitch-guard-layout.patch)). The first build still jumped, with 53 forward jumps logged, and the result was open when written ([log](https://github.com/sortedcord/MotoBook60Pro-Hackintosh-EFI/blob/main/accel/LOG.md)). It matters if our pad shows jumps under polling. The patch is GPL-3.0, ideas only. Confidence: Medium for the glitch, Low for the fix.
- **INTC1084 appears to belong to the Meteor Point pin driver in Linux.** The kernel driver database lists `INTC1084` under `pinctrl-meteorpoint.c`, while `INTC105E` (Arrow Lake-H/U) is in the Meteor Lake driver ([LKDDB](https://cateee.net/lkddb/web-lkddb/PINCTRL_METEORPOINT.html), [commit adding INTC105E](https://tangled.org/tjh.dev/kernel/commit/a366e46da10d7bfa1a52c3bd31f342a3d0e8e7fe)). So a VoodooGPIO table for our touchpad would follow the Meteor Point pad layout, not the Meteor Lake one. No source I found confirms the Arrow Lake-HX mapping. The kernel code is GPL, so layout reading only. Confidence: Low to Medium.
- **VoodooI2C #595 and #591 are unchanged since our earlier read.** No new reviews. The same author opened VoodooI2CHID #84 for [#590](https://github.com/VoodooI2C/VoodooI2C/issues/590) (contact identifier used as a wrapper index drops touches on a Goodix screen) and #85 for [#592](https://github.com/VoodooI2C/VoodooI2C/issues/592). The SYNA3602 override replaces the descriptor of real Synaptics pads, so it only matters if our pad is a SYNA3602.
- **Polling does not replace the controller interrupt.** [#593](https://github.com/VoodooI2C/VoodooI2C/issues/593) shows `-vi2c-force-polling` still needs the DesignWare controller IRQ. On an Alder Lake ASUS the controller never starts and the touchpad chain is not published. The author offers an opt-in controller polling fallback. Not our case today, useful if a 275HX controller fails the same way. Confidence: Medium (single report). VoodooI2C is GPL-3.0.
