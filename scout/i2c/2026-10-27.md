## Notable

**VoodooI2C: first code change in eleven months.** [6be653a](https://github.com/VoodooI2C/VoodooI2C/commit/6be653a2d2)
(PR #586) adds I2C and GPIO support for Tiger Lake, Alder Lake and Raptor Lake, fixes the Alder Lake-S GPIO interrupt
layout and moves the VoodooGPIO submodule. No Arrow Lake IDs. It touches the controller driver files our Arrow Lake
patches also change, so the next rebase needs a careful diff. High confidence.

## Second run (Mac, window 2026-10-27 09:29 to 18:11 UTC)


### Actionable

**VoodooI2C master no longer has `VoodooI2CPCILakeController`, so LegionI2CArrowLake 1.1.0 does not bind on a master
or nightly build.** The class was removed in
[054d5d1](https://github.com/VoodooI2C/VoodooI2C/commit/054d5d1297) (PR #575, 2025-11-25), which moved the D0 write into
the plain `VoodooI2CPCIController`. The 2.9.1 release (2024-11-06) still has the class our personality names. The
ASUS FX608LP repo (CENSEDAXIS20025, a 275HX with an ELAN `04F3:32E2` pad on `8086:7F4E`) hit this first. We answered on
[LegionI2CArrowLake#1](https://github.com/watchthelight-labs/LegionI2CArrowLake/issues/1#issuecomment-6450246184) and
rewrote the install step to say "use the 2.9.1 release", with credits for that repo and for bafcz
([6d6c919](https://github.com/watchthelight-labs/LegionI2CArrowLake/commit/6d6c919413251578995d967e64bbce41d656a4f7)).
That repo also reports a second cause on its machine: VoodooI2C checks the APIC pin first, and the pad's pin (0x2c)
passes the "at or below 0x2f" test, so the function returns before `-vi2c-force-polling` is read and the controller
stays in APIC mode although the interrupt never delivers; VoodooI2CHID then builds an interrupt source that never fires
and leaves its 200 ms timer off. Their fix patches both kexts. Our pad works in polling mode on the 2.9.1 release, so
we are not in that case, but another 275HX laptop may be. We have not checked their patches. High confidence on the
master change (commit read), Medium on the rest.

### Notable

- VoodooI2C [PR #586](https://github.com/VoodooI2C/VoodooI2C/pull/586) (merged 2026-10-25) adds Tiger, Alder and
  Raptor Lake I2C and GPIO data. Linux maps INTC105E and INTC1083 to the Meteor Lake-P table, INTC1082 to Meteor
  Lake-S, and INTC1084 to a separate Meteor Point table with five communities. Our DSDT's TPD0 device returns INTC1084,
  so an interrupt-driven pad needs that table in VoodooGPIO, which no one has written for macOS.
- bafcz/Hackintosh_LegionY9000P-IRX8_RaptorLake-HX (GPL-3.0) runs an ELAN06FA pad on interrupts through a modified
  VoodooI2C and a VoodooGPIO pin table; credited in the LegionI2CArrowLake README.
- wsjj-official/EFI-2025Y9000P v0.6: BE200 Wi-Fi driver update, Y9000P 83F5 audio. Not our hardware.
