# mt7925-wifi-native: 2026-10-29 (window 2026-10-28 11:14 to 2026-10-29 10:00 UTC)

RTL8814Native spent the night reverse engineering AWDL: 50 commits of notes and a first, untested stage 1 code drop.
It is the most detailed public map so far of what a third-party IO80211 driver must provide for `awdl0`, and it is
directly useful for [our AWDL issue #2](https://github.com/watchthelight-labs/WTLWifiMenu/issues/2),
which has not been started.

## Notable

**DrogaBox/RTL8814Native AWDL notes** ([repo](https://github.com/DrogaBox/RTL8814Native), `Docs/AWDL_*.md`, written in
Spanish). Licence: GPL-2.0 (the LICENSE file is the Realtek GPL-2.0 header), so ideas and facts only, no code. The
findings were taken with IDA from the kernel collection and from `wifip2pd` on Darwin 25.6.0, with the addresses
re-checked by script. They are claims to re-check against our own 25G332 dump, not proof. Medium confidence overall,
High that the documents say what is summarised here.

- AWDL gate: `wifip2pd` reads `CARD_CAPABILITIES` (type 12) and tests bit 0 of byte +0x08 before it asks for an AWDL
  interface ([e7b9b3f](https://github.com/DrogaBox/RTL8814Native/commit/e7b9b3f688), `AWDL_PROTOTYPE_DESIGN.md` 1.1).
- Creation: `VIRTUAL_IF_CREATE` (type 94) has a 32-byte payload: MAC at +0x04, role at +0x0C (6 = AWDL), and the
  driver writes the BSD name back at +0x10. The generic `createVirtualInterface` accepts only role 7. Broadcom builds
  role 6 privately (`AppleBCMWLANCore::setVIRTUAL_IF_CREATE` then `createProxInterface`)
  ([5232b82](https://github.com/DrogaBox/RTL8814Native/commit/5232b826e6),
  [ca8bbcb](https://github.com/DrogaBox/RTL8814Native/commit/ca8bbcb9e5)).
- The 30 s wait in `wifip2pd` ends on an IORegistry match, not on an Apple80211 event. The new service needs
  `IOInterfaceName`, a `SIOCGIFMEDIA` media word with `(ifm_current & 0xE0) == 0x80`, a live BSD index and
  `IO80211VirtualInterfaceRole = AirLink` ([d74b61b](https://github.com/DrogaBox/RTL8814Native/commit/d74b61b026),
  [24e62b2](https://github.com/DrogaBox/RTL8814Native/commit/24e62b2fb5),
  [184fe7b](https://github.com/DrogaBox/RTL8814Native/commit/184fe7b8cb)).
- Class chain: `AppleBCMWLANProximityInterface` subclasses `IO80211AWDLProtocol`, which subclasses
  `IO80211VirtualInterface`. The notes list 64 pure virtual slots, each reachable through a same-named apple80211 bridge
  ([7445b61](https://github.com/DrogaBox/RTL8814Native/commit/7445b61e68),
  [48ee825](https://github.com/DrogaBox/RTL8814Native/commit/48ee825eaa),
  [875f02a](https://github.com/DrogaBox/RTL8814Native/commit/875f02ab53)). The kernel collection exports vtables,
  `gMetaClass` and constructors for these classes, so a kext can subclass them without a KDK
  ([c8d0152](https://github.com/DrogaBox/RTL8814Native/commit/c8d01520f9)).
- Protocol in software: `IO80211AWDLPeerManager` already does master election, the sync tree, the TLV templates, the
  peer table and the timers. A driver inherits it through `createPeerManager` and only has to transmit the sync frame
  template on schedule, post the availability-window events 41/42/43, follow the channel sequence, deliver AWDL action
  frames and serve the TX pull ([63da491](https://github.com/DrogaBox/RTL8814Native/commit/63da49125f),
  [048c706](https://github.com/DrogaBox/RTL8814Native/commit/048c70686b),
  [6c2d2d1](https://github.com/DrogaBox/RTL8814Native/commit/6c2d2d176e)).
- Their plan is staged. Stage 1 is "`awdl0` accepted by `wifip2pd`, no peers", with an exact request list (12, 94,
  97, event monitoring, the usual ifnet ioctls) ([ce85df3](https://github.com/DrogaBox/RTL8814Native/commit/ce85df3a5f)).
  The stage 1 code and an unapplied hook patch are in
  [e44d308](https://github.com/DrogaBox/RTL8814Native/commit/e44d30882d), and the post-create ioctls 130/131 were
  resolved last ([d0d4a0a](https://github.com/DrogaBox/RTL8814Native/commit/d0d4a0aac1)). Nothing has been shown
  working on hardware yet.

Why it matters: on the MT7925, the hard part of AWDL is timing (sync frames on a shared timeline, channel hops, a second
MAC). Per their notes the firmware would carry that, while the kernel's peer manager carries the protocol. Stage 1 is a
cheap feasibility spike we could plan against our own dump. Their per-build header `IO80211AWDL_25_6_0.h` is a second
reference to check our 25G332 slots against.
